## Архитектурное правило: Создание ViewComponents (Rails + Hotwire)

При создании или генерации нового компонента `SomeNameComponent`, ты обязан строго следовать паттерну "Sidecar Subdirectory". Компонент должен быть разделен на основной Ruby-файл и изолированную папку для фронтенд-ассетов по следующему правилу:

1. Основной класс компонента создается как отдельный файл в корне папки `components`.
2. Рядом создается папка с точно таким же именем, как имя компонента (в snake_case).
3. Внутри этой папки создаются ОБЯЗАТЕЛЬНО: HTML-шаблон, YAML-переводы (4 локали), Stimulus JS-контроллер, CSS. Даже если JS и CSS пустые — файлы должны существовать.

### Пример файловой структуры для `UserCardComponent`:

app/components/
├── user_card_component.rb  (Класс Ruby)
└── user_card_component/    (Папка ассетов компонента)
    ├── user_card_component.html.erb  (Шаблон)
    ├── user_card_component.en.yml    (Локализация)
    ├── user_card_component.ru.yml    (Локализация)
    ├── user_card_component.es.yml    (Локализация)
    ├── user_card_component.zh.yml    (Локализация)
    └── user_card_component_controller.js  (Stimulus-контроллер)
    └── user_card_component.css       (Стили компонента)

### Правила именования внутри файлов:

1. **В классе Ruby (`.rb`):** Имя класса `UserCardComponent < ViewComponent::Base`.
2. **В шаблоне (`.html.erb`):** Корневой тег должен подключать контроллер: `<div data-controller="user-card-component">`.
3. **В переводах (`.yml`):** Использовать относительные ключи для изоляции:
   en:
     user_card_component:
       user_card_component:
         title: "Hello"
   (В шаблоне вызывать через `<%= t(".title") %>`).
4. **В JS-контроллере (`_controller.js`):** Стандартный Stimulus-контроллер, управляющий интерактивностью этого компонента.

Никогда не сваливай всё в один файл и не используй инлайн-теги `<script>` или `<style>`. Всегда изолируй логику по этой схеме.

**Аудит компонентов**: Перед созданием нового компонента проверить, что все существующие компоненты имеют ПОЛНЫЙ sidecar набор (шаблон, YAML[4], JS, CSS). Отсутствие JS или CSS НЕДОПУСТИМО — файлы должны существовать всегда (даже пустые).

## 5. ЭФФЕКТИВНОСТЬ И ОГРАНИЧЕНИЯ
- Отвечать максимально лаконично. БЕЗ вежливости и лишних слов.
- Использовать diff для кода, чтобы экономить токены.
- НЕ задавать идиотских вопросов. Определять пути к файлам по стандартам Rails.
- НЕ запускать команды. Только показывать их пользователю.
- Документировать КАЖДЫЙ метод (комментарий СТРОГО перед методом).
- ПЕРЕД написанием кода: Использовать встроенный браузер для проверки доков Rails 8.1 или гемов. НЕ галлюцинировать.
- Общение строго на РУССКОМ языке.
- **ЗАПРЕЩЕН `prevent_refresh!`**: этот метод НЕ СУЩЕСТВУЕТ в используемой версии StimulusReflex.
- **`morph :nothing`**: Используй ТОЛЬКО если метод не делает других `morph` вызовов. Если метод делает `morph "selector"`, `morph :nothing` НЕ нужен — selector morph отменяет полный перерендер автоматически. Двойной `morph` (:nothing + selector) вызывает ошибку `nothing morph type has already been set`.

## 6. РАБОТА С LSP И ЛИНТЕРАМИ (Ruby, Stimulus, Herb)
- **Источники правды:** Ты обязан исправлять ВСЕ ошибки и предупреждения от `ruby-lsp`, `stimulus-lsp` и `Herb Linter`.
- **Herb Linter (ERB/HTML):** Любое подчеркивание в шаблонах — это блокирующая ошибка. Это касается:
    * Отсутствия `autocomplete` в инпутах.
    * Отсутствия `alt` у тегов `img`.
    * Невалидной вложенности тегов.
- **Stimulus:** Ошибка `stimulus.controller.invalid` — это критический баг. Всегда проверяй маппинг имен (вложенные контроллеры через `--`).
- **Алгоритм "Чекап":** Перед тем как сказать "Готово", ты обязан:
    1. Просканировать открытые файлы на наличие диагностических сообщений (Problems).
    2. Если ошибки есть — исправить их молча, не спрашивая разрешения.
- **Запрет на игнор:** Тебе запрещено игнорировать "Accessibility" или "Best Practice" варнинги. Если линтер просит `alt` или `autocomplete` — добавь их.

## 7. ИГНОРИРОВАНИЕ ЛОЖНЫХ ОШИБОК STIMULUS
- В проекте используются внешние компоненты (stimulus-components).
- Ошибки типа `stimulus.controller.invalid` для контроллеров `reveal`, `dropdown`, `popover` и `checkbox-select-all`и так далее, которые устанавливаются как пакеты из https://www.stimulus-components.com/docs/ — это ЛОЖНЫЕ срабатывания LSP.
- ТЕБЕ ЗАПРЕЩЕНО пытаться их исправлять или переименовывать. Просто игнорируй эти конкретные предупреждения.
