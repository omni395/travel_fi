## Архитектурное правило: Создание ViewComponents (Rails + Hotwire)

При создании или генерации нового компонента `SomeNameComponent`, ты обязан строго следовать паттерну "Sidecar Subdirectory". Компонент должен быть разделен на основной Ruby-файл и изолированную папку для фронтенд-ассетов по следующему правилу:

1. Основной класс компонента создается как отдельный файл в корне папки `components`.
2. Рядом создается папка с точно таким же именем, как имя компонента (в snake_case).
3. Внутри этой папки создаются ОБЯЗАТЕЛЬНО: HTML-шаблон, YAML-переводы (4 локали), Stimulus JS-контроллер, CSS. Даже если JS и CSS пустые — файлы должны существовать.

### Пример файловой структуры для `UserCardComponent`:

app/components/
├── user_card_component.rb  (Класс Ruby)
└── user_card_component/    (Папка ассетов компонента)
    ├── user_card_component.html.erb  (Шаблон)
    ├── user_card_component.en.yml    (Локализация)
    ├── user_card_component.ru.yml    (Локализация)
    ├── user_card_component.es.yml    (Локализация)
    ├── user_card_component.zh.yml    (Локализация)
    └── user_card_component_controller.js  (Stimulus-контроллер)
    └── user_card_component.css       (Стили компонента)

### Правила именования внутри файлов:

1. **В классе Ruby (`.rb`):** Имя класса `UserCardComponent < ViewComponent::Base`.
2. **В шаблоне (`.html.erb`):** Корневой тег должен подключать контроллер: `<div data-controller="user-card-component">`.
3. **В переводах (`.yml`):** Использовать относительные ключи для изоляции:
   en:
     user_card_component:
       user_card_component:
         title: "Hello"
   (В шаблоне вызывать через `<%= t(".title") %>`).
4. **В JS-контроллере (`_controller.js`):** Стандартный Stimulus-контроллер, управляющий интерактивностью этого компонента.

Никогда не сваливай всё в один файл и не используй инлайн-теги `<script>` или `<style>`. Всегда изолируй логику по этой схеме.

**Аудит компонентов**: Перед созданием нового компонента проверить, что все существующие компоненты имеют ПОЛНЫЙ sidecar набор (шаблон, YAML[4], JS, CSS). Отсутствие JS или CSS НЕДОПУСТИМО — файлы должны существовать всегда (даже пустые).

## 3. АРХИТЕКТУРНЫЙ ПОТОК (эталон, обязательный)
- Цепочка: Controller/Reflex (доступ/Pundit) -> Service (бизнес-логика) -> Model (только данные) -> PaperTrail -> VersionObserverJob -> Broadcaster -> CableReady -> ActionCable -> DOM.
- **Reflex**: `morph :nothing` + `deep_symbolize_keys(params)` + `authorize_with_pundit!` → делегирует в Service. НЕ рендерит DOM после сохранения (обновление — только через Broadcaster).
- **Service**: вся бизнес-логика; `Model.save!`/`update!` строго внутри транзакции.
- **Broadcaster**: рендер зон (`helpers.render`) + `cable_ready["AdminChannel"].inner_html(selector:, html:)` + `.broadcast`. Только `inner_html`, НЕ `morph`.
- **VersionObserverJob**: маршрутизация по `version.item_type` → ветка `handle_<model>_update` → `XxxBroadcaster.call`.
- **ViewComponent**: только презентация (sidecar 7 файлов, 4 локали).
- НЕТ логики в моделях. НЕТ логики в контроллерах. НЕТ логики рассылок в моделях.

## 5. ЭФФЕКТИВНОСТЬ И ОГРАНИЧЕНИЯ
- Отвечать максимально лаконично. БЕЗ вежливости и лишних слов.
- Использовать diff для кода, чтобы экономить токены.
- НЕ задавать идиотских вопросов. Определять пути к файлам по стандартам Rails.
- НЕ запускать команды. Только показывать их пользователю.
- Документировать КАЖДЫЙ метод (комментарий СТРОГО перед методом).
- ПЕРЕД написанием кода: Использовать встроенный браузер для проверки доков Rails 8.1 или гемов. НЕ галлюцинировать.
- Общение строго на РУССКОМ языке.
- **ЗАПРЕЩЕН `prevent_refresh!`**: этот метод НЕ СУЩЕСТВУЕТ в используемой версии StimulusReflex.
- **`morph :nothing`**: Используй ТОЛЬКО если метод не делает других `morph` вызовов. Если метод делает `morph "selector"`, `morph :nothing` НЕ нужен — selector morph отменяет полный перерендер автоматически. Двойной `morph` (:nothing + selector) вызывает ошибку `nothing morph type has already been set`.
- **Зарезервированные ключи StimulusReflex**: `id`, `params`, `selectors`, `morph`, `attrs`, `flash`, `event`, `permanent_attribute_name` — НЕЛЬЗЯ передавать как top-level ключи объекта-аргумента в `this.stimulate("Reflex#method", obj)` (объект станет опциями, `args` придет пустым → `RecordNotFound: ... without an ID`). Используй неймспейсные ключи (`field_id`, `poi_category_id`) или `{ params: {...} }`. Из распарсенных FormData обязательно удаляй `id` (`delete params.id`).
- **Reflex не рендерит DOM**: методы, меняющие состояние (create/update/destroy), делают `morph :nothing` и вызывают Service. Селекторный морф в Reflex — только для чтения (пагинация/фильтры). Обновление UI после сохранения — только через Broadcaster (`VersionObserverJob` → CableReady), иначе гонки двух морфов одного селектора.
- **Broadcaster — только `inner_html`**: НЕ используй CableReady `morph` для обновления зон из Broadcaster — падает на `undefined.dispatchEvent` (`parent.children[idx]`). Используй `inner_html` по селектору-обёртке.
- **Рендер вложенных ViewComponent из фонового job**: в компонентах, которые рендерит Broadcaster (SolidQueue worker), вложенные ViewComponent рендери ТОЛЬКО через `<%= render %>` (шаблон) или `helpers.render` (метод компонента) — view_context. Запрещён вложенный `ApplicationController.render` — падает в контексте job, зона молча не отправляется. Per-entry устойчивость — через `rescue` в методе компонента (см. `AuditLogComponent#render_entries_html`).
- **Broadcast из worker (bin/jobs)**: инициализируй ActionCable PubSub до `SolidQueue::Cli.start`: `ActionCable.server.config.cable = { "adapter" => "solid_cable" }` (СТРОКОВЫЙ ключ — `cable.fetch("adapter") { "redis" }`; символьный `:adapter` → Redis), затем `ActionCable.server.pubsub`.
- **pagy() в Broadcaster**: в SolidQueue worker нет `request` → `NameError: request`, зона с пагинацией не отправляется (симптом: show/fields работают, POIs/Audit нет). Добавь mock `def request; @request ||= ActionDispatch::Request.new({}); end`.
- **Чекбоксы (Rails check_box)**: hidden(value=0)+checkbox с одним `name`. В JS — `input[name='...'][type='checkbox']`, иначе false не сохраняется.
- **Единый паттерн админ-сущности** — см. README «🗂 Единый паттерн админ-сущности» (компоненты Index/Show+табы/Edit, Reflex, Service, Broadcaster, AdminChannel, VersionObserverJob, Ui::AuditEntryComponent).
- **Контейнер-цель отдельно от содержимого**: селектор цели (`[data-...]`) — на обёртке в шаблоне страницы, корень компонента — БЕЗ этого селектора (иначе `inner_html` создаёт вложенность).
- **Нормализация params**: параметры из JS приходят со строковыми ключами. В Reflex обязательно `deep_symbolize_keys(params)` (метод в `ApplicationReflex`) перед передачей в Service, иначе `params.slice(:attr)` вернёт пустой хэш.
- **Аудит**: используй `update!`/`save!` (создают PaperTrail-версии → Broadcast). `update_all` НЕ создаёт версии и НЕ триггерит Broadcast — недопустим для данных с аудитом (в т.ч. реордер позиций).
- **Клиент CableReady**: применяй операции по одной (`forEach` + `try/catch`), пропуская морфы на отсутствующие в DOM селекторы.
- **ЗАПРЕТ на упоминание удалённого/перенесённого кода в ROADMAP/README**: НИКОГДА не писать в документации, что какой-то сервис/метод/файл «удалён», «перенесён», «консолидирован» или «раньше был X». Документация фиксирует ТОЛЬКО актуальное состояние: что работает, что в планах, что является багом/долгом. Упоминания прошлого кода засоряют ROADMAP и запрещены.

## 6. РАБОТА С LSP И ЛИНТЕРАМИ (Ruby, Stimulus, Herb)
- **Источники правды:** Ты обязан исправлять ВСЕ ошибки и предупреждения от `ruby-lsp`, `stimulus-lsp` и `Herb Linter`.
- **Herb Linter (ERB/HTML):** Любое подчеркивание в шаблонах — это блокирующая ошибка. Это касается:
    * Отсутствия `autocomplete` в инпутах.
    * Отсутствия `alt` у тегов `img`.
    * Невалидной вложенности тегов.
- **Stimulus:** Ошибка `stimulus.controller.invalid` — это критический баг. Всегда проверяй маппинг имен (вложенные контроллеры через `--`).
- **Алгоритм "Чекап":** Перед тем как сказать "Готово", ты обязан:
    1. Просканировать открытые файлы на наличие диагностических сообщений (Problems).
    2. Если ошибки есть — исправить их молча, не спрашивая разрешения.
- **Запрет на игнор:** Тебе запрещено игнорировать "Accessibility" или "Best Practice" варнинги. Если линтер просит `alt` или `autocomplete` — добавь их.
